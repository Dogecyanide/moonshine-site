Installing

Wii (console)

  1. Download the English Launcher or Nihongo Ranchā ZIP.
  2. Copy its contents to the root of your SD card, so the moonshine_launcher folder ends up in your apps folder.
  3. Start it from the Homebrew Channel, select your version and settings, and enjoy.

USB loading has caused some issues in the past, so loading from SD is preferred.

Updating? Replace the app files and use the launcher and mod files from the same ZIP. If you still have apps/susamune_launcher, rename it to apps/moonshine_launcher first. Your settings, records, ghosts and states live in /Moonshine data.

Dolphin (emulator)

  1. Download a Dolphin ZIP.
  2. Apply the matching BPS patch to your own clean ISO with a BPS patcher such as Floating IPS. The patch verifies the source image first.
  3. Give Moonshine a memory card in slot B so your settings persist; slot A stays for your normal save. Ghosts and online need a few more Dolphin settings: see the guidebook's Dolphin chapter.
  4. For goop to save and load correctly with savestates, set Graphics → Hacks → Texture Cache Accuracy to Safe.

Dolphin has full parity with Wii, so every feature works on both, including online play against Wii players and Delfino Ghosts. Files are saved on the memory card, so space is limited and saving takes a little longer than on an SD card.

We strongly advise against running Moonshine with Gecko codes enabled. They will either break Moonshine's features or be broken by them. On Wii, also turn Native Controls on in the launcher's Settings (Nintendont's Native Control option). GameCube hardware is not supported.

What's inside

  • Savestates with 3 slots to supercharge your practice, and you can save them to your SD card for later.
  • Practice codes, better than ever: every old Gecko code is ported and many are improved. Timer, metadata, level select and more.
  • Ghosts to watch, race or share, plus community ghosts to download from Delfino Ghosts! Scrub through a run, then take over from the ghost and finish out the IL!
  • Frame advance, on-console TASing and a free camera with camera paths. Make it your way.
  • IL system with integrated PBs, a PB fanfare and achievements!
  • Customise everything, from the timer to the colour of Mario's shoes. Nearly everything in Moonshine is yours to personalise, down to gradients and animations.
  • Online play: race up to 3 friends live in ILs, Stageloader runs or draft sets, with a score bar on screen. Wii and Dolphin can play together.
  • Practice tools like slowed gameplay and a collision viewer, and a menu search to find any setting in seconds.

Button bindsボタン割り当て

A bind is a combo of up to four buttons. It has to match exactly: holding extra buttons stops it from firing. The savestate Save and Load shortcuts are the exception: they also work while you hold other gameplay buttons (A+B during frame advance, for example) and don't repeat while held. Binds work even while the game has disabled your controller, such as during dialogue.

Make it yours

Many features start unassigned, so you can bind them however you like. Some useful ones:

  • Slowdown: toggle preset switches between 100% and your Slowdown preset speed.
  • Savestate: save / load State 2 and State 3 use one slot directly, whatever Save to and Load from are set to.
  • Quick toggles for Fast text, FLUDD in secrets, Area lock, Infinite juice, Nozzle lock, Stage intro skip, No shine get animation, Fruit never times out, Mute background music, Shadow Mario HP meter, Unlock Yoshi and Unlock nozzles.

Changing a bind

  1. Open System > Button binds. C-stick Left/Right jumps between sections.
  2. Highlight an action and press A to record a combo.
  3. Hold the buttons you want, then release one to set it. Pressing a fourth button also sets it. Press the C-stick to cancel.
  4. Press X on a bind to clear it.

Pause, step, free camera and TAS actions can also be rebound on their own pages with X, and cleared with Z. The sticks can't be part of a bind. Binds are stored per region in moonshine.ini and can be edited by hand, for example savestate_save = DLeft.

Savestatesステート

Three memory slots, like emulator savestates, on real Wii hardware and in Dolphin. The default shortcuts are D-Left to save and D-Right to load.

  • Save to picks the slot your Save shortcut writes to. Load from separately picks what your Load shortcut restores. Change either with A or C-stick Left/Right; choosing a slot doesn't save or load anything. You can Save to State 1 while you keep practising from State 2.
  • Each state shows Saved or Empty. Optional cycle save slot and cycle load slot shortcuts, and direct save and load shortcuts for State 2 and State 3, can be set in System > Button binds.
  • Hold Load to keep gameplay still after the restore, then release when you're ready. If the state was saved during an intro, the intro finishes first; keep holding to stop on Mario's first controllable frame.
  • A state only loads in the same stage and episode it was saved in.
  • States include ghost data, so the ghost recording is saved and restored along with the game.
  • Any state can be saved to the SD card and shared with other players. See SD states.
  • Clear save slot empties the Save to slot after you confirm. The other states stay saved.

  • Save to（保存先）で保存するスロットを、Load from（読込元）で読み込む対象を別々に選べます。AまたはCスティック左右で切り替え、選ぶだけでは保存・読込は行いません。たとえば Save to を State 1、Load from を State 2 にすると、State 1 を上書きしながら State 2 からの練習を続けられます。
  • 各ステートには Saved（保存済み）または Empty（空き）と表示されます。System > Button binds で cycle save slot と cycle load slot のショートカットや、State 2・State 3 を直接保存・読込するショートカットも設定できます。
  • Load を押し続けると、読込後もゲームを止めておけます。離すと動き出します。イントロ中に保存したステートはイントロが先に終わり、押し続けるとマリオを操作できる最初のコマで止まります。
  • 読み込みには保存時と同じステージとエピソードが必要です。
  • ステートにはゴーストのデータも含まれ、ゴースト録画もゲームと一緒に保存・復元されます。
  • どのステートもSDカードに保存して、他のプレイヤーと共有できます。詳しくは SDステート を参照してください。
  • Clear save slot は確認後に Save to のスロットを消します。他のステートは残ります。

SD statesSDステート

Keep a memory state on SD so it survives a reboot.

  1. Make a normal memory savestate and choose its slot under Save to.
  2. Open SD states > Save memory state to SD. Type a name, confirm with Start, and wait until saving finishes. X+Start cancels naming. The file is a new .mss in /Moonshine data/states.
  3. Later, with the same mod build, game region and launcher setup, enter the same level and episode. Secret areas also need the same parent episode.
  4. Open SD states > Refresh / first page and highlight your file.
Button on a fileAction
Y Load fromMakes this file the target of your normal Load shortcut. Your three memory slots stay intact.
A ImportAfter confirmation, copies the file into the Save to slot. Load from stays unchanged.
Start RenameEdits the display name. Start finishes; X + Start cancels.
X DeleteDeletes the SD file after confirmation. Memory states are unaffected.
  • Loading from SD reads the file each time, so it can be slower than a memory load.
  • Large files can load even when all three slots are full, as long as one slot holds a working state for the current scene. That state is the recovery point: if a read fails mid-load, the game restores it and tells you which slot it used. With no recovery state and too little temporary space, the load is refused safely.
  • The game checks that its loaded resources match the state, so a matching level name alone may not be enough. Unsupported, incompatible or damaged files are refused before a memory slot is replaced.

TAS projectsTASプロジェクト

A TAS keeps Mario's recorded inputs, its Beginning and up to two checkpoints together under one name.

  1. New TAS where the recording should begin. The Beginning is saved automatically, including the RNG, and gameplay stays paused.
  2. Hold Mario's buttons and press Step to record one frame, or Resume to record normal play. Opening the menu pauses your work.
  3. Checkpoints > Save Checkpoint 1 before a move you might redo. Go to Checkpoint 1 returns there; Step or Resume records a new continuation. Checkpoint 2 works the same way.
  4. Replay plays the inputs from the Beginning. B or Start stops it.
  5. Scrub recording shows the recorded inputs on a timeline. Left/Right moves 1 frame, Up/Down 30 and L/R 300; X jumps to the beginning and Y to the end. A previews the selected frame in the paused game, and Continue from there replaces the recorded future from that frame. Checkpoints show green in this area and gray in another.
  6. Save TAS, enter a name and confirm with Start. It saves the whole recording, the Beginning and any checkpoints to /Moonshine data/tas. Later saves update the same TAS.
  7. Open TAS later with the same build, region and setup. In the list, Start renames and X deletes the SD copy, with confirmation.
  • Go to Beginning, Go to Checkpoint and Open TAS leave you paused and ready to edit. Later inputs stay available for Replay until your first new Step or Resume.
  • Continue stays paused so you can set up the next input. Use it after stopping a take or finishing a Replay.
  • Saving over a checkpoint asks first: A replaces, B keeps it.
  • Limits: 4096 frames and 32 area or movie transitions per take. The header shows the count, for example 200/4096. Inputs during intros, fades, talks and movies are recorded too; loading waits use no frames. If a limit is reached, recording stops and the take is kept.
  • TAS projects use the same three memory slots as savestates. If a new TAS needs an occupied slot, it asks which state to replace.
  • Replay is experimental. If the game differs from the recording, DESYNC fN shows the first frame that differed and playback continues. f0 means the starting state already differed.
  • For Replay and Go to Beginning, return to the area and episode where the TAS began yourself.
  • TAS banner (On by default) shows progress and help text. Turn it off here or in Display > HUD and displays > Other HUD.
  • TAS projects can't be shared across regions or builds. Export a ghost to share a finished attempt.

Online playオンライン対戦

Race friends live, or just explore together. A room holds 2 to 4 players, and the consoles connect directly (peer to peer). Wii and Dolphin players can play each other.

What you need

  • An internet connection for every player, even on the same router: it's used to find each other's address.
  • The same Moonshine build. JP, US and PAL can share a room; PAL must run at 60 Hz.
  • On Wii, the console's own internet settings. In Dolphin, Serial Port 1 set to Broadband Adapter (HLE) (see Dolphin).
  • Not supported: two players both on phone mobile hotspots. Some strict NAT or router setups can't connect either.

Connecting

  1. Open the Online tab and enter an Online name (up to 16 characters).
  2. The host sets Room size (2, 3 or 4 players) before connecting, then chooses Create room. Everyone else chooses Join room.
  3. Swap codes. Your code is 14 characters. Each guest types the host's code into Friend's code. The host enters each guest's code in Guest 1 code (and Guest 2 and Guest 3 code in bigger rooms).
  4. On the same router, exchange the Same-network codes instead.
  • Your code stays the same for about 90 days, then changes. If it changed, the game says Your code changed - resend it.
  • Players are saved when they connect. In the code keyboard, Y opens Saved codes.
  • The host can select a connected guest to kick them. They can't rejoin until the host enters their code again.

Race setup

The host chooses the mode. Before racing, changes apply to everyone and clear Ready. After a match, the host picks the next setup and chooses Apply next setup.

ModeHow it works
Free roamExplore together. The host can set up a race at any time.
IL racingPick an IL and a Best of (1, 3, 5 or 7). Everyone chooses Ready; the fastest finish wins the round. A tie means ready again.
Stageloader raceRace through the host's Stageloader playlist. Each player advances independently.
Draft setChoose an IL pool (Any%, All ILs or Non-Any%) and a set length (Best of 3 or 5); each IL is a Best of 3. With 2 players, five ILs are drawn and players take turns to ban and pick; after each IL, the winner bans one and the loser counterpicks. With 3 or 4 players, one more IL than players is drawn, everyone bans one in turn, and the IL left over is raced.
  • Forfeit race gives up the current race; you stay in the room and the others can finish. The host's End race cancels the whole match or playlist with no winner, and everyone stays in the room.
  • Assists void the round (Assisted - round void), and slowed gameplay can't win.

Seeing other players

  • Other players appear as Shadow Mario, Piantissimo or Mario (Opponent model), in their own Mario colours. In a 2 player room, Opponent inputs can show their controller.
  • Their movement is smoothed (interpolated) from their updates, so they may look slightly behind. Nothing in your own game is rewound.
  • The score bar sits at the top centre. Show or hide it, and restyle it with Edit score bar. With 3 or 4 players it lists everyone with their IL and set wins, then each time after a round, marked forfeit, DNF or assisted where it applies.

If it won't connect

  • Check both codes. A firewall may block play.
  • Connection help > NAT test checks your router. SAME - should work is good; DIFFERENT - symmetric means a direct connection will fail from this network.
  • There's no relay server to fall back on. Try another network, such as one player on a different internet connection.
  • Online sessions are logged in /Moonshine data/logs. Include the log when you report a connection problem.

Setting up Dolphin for 3.0.0

The quick way: extract the Dolphin download to a folder you'll keep and install 64-bit Python 3.10 or newer.   1. Memory: Moonshine needs Dolphin's memory override for the game, with MEM1 at 32 MiB (RAMOverrideEnable = True, MEM1Size = 33554432) and MMU = False. Ghosts need this.
  2. Moonshine data: slot B is a GCI Folder memory card for Moonshine; slot A stays for your normal Sunshine save. Tips and reportsヒントと不具合の報告

Gotchas

  • Bind overlaps: the attempt counter's Show and Add binds share D-Left / D-Right with savestates, which is why they only work with In-stage counter controls On.
  • Z and the warp wheel: leave Disable Z Menu On, or Z also opens the retail menu.
  • Binds need an exact match. If one won't fire, check that you aren't holding an extra button.
  • TAS next to the timer means the attempt used an assist. Restart the stage for a PB-eligible attempt.
  • A state won't load? You need the same stage and episode, build and setup. Savestate errors show unless you turned Savestate errors Off.
  • No Gecko codes. Keep Cheats off in the launcher's Settings; Moonshine already includes nearly all the GCT generator practice codes. Turn Native Controls on there too.

Reporting a problem

  • Include the game region, scene, settings, steps to reproduce and the build checksum shown in game.
  • Crash history is in /Moonshine data/crashes, up to 16 recent reports. Keep the matching text, .bin and .core files from the same report together. The optional tools/decode_crash.py script reads the binary reports with Python 3.
  • Questions and reports go to the Moonshine Discord or the GitHub issues.

注意点

  • ボタンの重なり：試行カウンターの表示・追加は、ステートと同じ十字キー左右を使います。そのため In-stage counter controls がOnのときだけ使えます。
  • Zとワープホイール：Disable Z Menu はOnのままにしてください。Offにすると、Zで本来のメニューも開きます。
  • 割り当ては完全一致が必要です。反応しない場合は、余分なボタンを押していないか確認してください。
  • タイマーの横の TAS は補助を使った試行という意味です。PB対象の試行にするにはステージを再開してください。
  • ステートが読み込めない場合：同じステージとエピソード、同じビルドと設定が必要です。Savestate errors をOffにしていなければエラーが表示されます。
  • Geckoコードは使わないでください。ランチャーの Settings で Geckoコード（Cheats）はオフにしてください。GCT generatorの練習コードはほぼすべて内蔵済みです。同じ画面でGCコントローラ直接接続（Native Controls）もオンにしてください。

不具合の報告

  • ゲーム版、場面、設定、再現手順、ゲーム内に表示されるビルドのチェックサムを書いてください。
  • クラッシュの記録は /Moonshine data/crashes に最新16件まで残ります。同じ報告のテキスト、.bin、.core ファイルはまとめて保管してください。任意の tools/decode_crash.py は、Python 3でバイナリの報告を読みます。
  • 質問や報告は Moonshine の Discord か GitHub の Issues へどうぞ。
