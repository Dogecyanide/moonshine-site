Installing

Wii (console)

  1. Download the English Launcher or Nihongo Ranchā ZIP.
  2. Copy its contents to the root of your SD card, so the moonshine_launcher folder ends up in your apps folder.
  3. Start it from the Homebrew Channel, select your version and settings, and enjoy.

USB loading has caused some issues in the past, so loading from SD is preferred.

Updating? Replace the app files and use the launcher and mod files from the same ZIP. If you still have apps/susamune_launcher, rename it to apps/moonshine_launcher first. Your settings, records, ghosts and states live in /Moonshine data.

Dolphin (emulator)

  1. Download a Dolphin ZIP.
  2. Apply the matching BPS patch to your own clean ISO with a BPS patcher such as Floating IPS. The patch verifies the source image first.
  3. Put a memory card in slot B so your settings persist.
  4. For goop to save and load correctly with savestates, set Graphics → Hacks → Texture Cache Accuracy to Safe.

As of 3.0.0, Dolphin has full parity with Wii, so every feature works on both.

We strongly advise against running Moonshine with Gecko codes enabled. They will either break Moonshine's features or be broken by them. On Wii, also turn Native Controls on in the launcher's Settings (Nintendont's Native Control option; Wii U doesn't have it). GameCube hardware is not supported.

What's inside

  • Savestates with 3 slots on Wii to supercharge your practice, and you can save them to your SD card for later.
  • Practice codes, better than ever: every old Gecko code is ported and many are improved. Timer, metadata, level select and more.
  • Ghosts to watch, race or share! You can even take over from one to finish out the IL!
  • Frame advance, on-console TASing and a free camera. Make it your way.
  • IL system with integrated PBs, a PB fanfare and achievements!
  • Customise everything, from the timer to the colour of Mario's shoes. Nearly everything in Moonshine is yours to personalise.

Getting started導入と起動

Moonshine is a practice mod for Super Mario Sunshine. It supports JP 1.0 (GMSJ01), US (GMSE01) and PAL (GMSP01). On Wii it runs through Nintendont from Moonshine Launcher; on PC it is a BPS patch for Dolphin. GameCube hardware is not supported.

Install on Wii

  1. Download the English Launcher or Nihongo Ranchā ZIP.

  3. Start it from the Homebrew Channel, pick your version and settings, and play.

Button bindsボタン割り当て

A bind is a combo of up to four buttons. It has to match exactly: holding extra buttons stops it from firing. In V2.3.3 the savestate Save and Load shortcuts are the exception: they also work while you hold other gameplay buttons (A+B during frame advance, for example) and don't repeat while held. Binds work even while the game has disabled your controller, such as during dialogue.

Make it yours

Many features start unassigned, so you can bind them however you like.

Changing a bind

  1. Open System > Button binds. C-stick Left/Right jumps between sections.
  2. Highlight an action and press A to record a combo.
  3. Hold the buttons you want, then release one to set it. Pressing a fourth button also sets it. Press the C-stick to cancel.
  4. Press X on a bind to clear it.

Pause, step, free camera and TAS actions can also be rebound on their own pages with X, and cleared with Z. The sticks can't be part of a bind. Binds are stored per region in moonshine.ini and can be edited by hand, for example savestate_save = DLeft.

Savestatesステート

Three memory slots, like emulator savestates, on real Wii hardware and in Dolphin. The default shortcuts are D-Left to save and D-Right to load.

  • Save to picks the slot your Save shortcut writes to. Load from separately picks what your Load shortcut restores. Change either with A or C-stick Left/Right; choosing a slot doesn't save or load anything. You can Save to State 1 while you keep practising from State 2.
  • Each state shows Saved or Empty. Optional cycle save slot and cycle load slot shortcuts can be set in System > Button binds.
  • Hold Load to keep gameplay still after the restore, then release when you're ready. If the state was saved during an intro, the intro finishes first; keep holding to stop on Mario's first controllable frame.
  • A state only loads in the same stage and episode it was saved in.
  • States include ghost data, so the ghost recording is saved and restored along with the game.
  • Any state can be saved to the SD card and shared with other players. See SD states.
  • Clear save slot empties the Save to slot after you confirm. The other states stay saved.

SD statesSDステート

Keep a memory state on SD so it survives a reboot.

  1. Make a normal memory savestate and choose its slot under Save to.
  2. Open SD states > Save memory state to SD. Type a name, confirm with Start, and wait until saving finishes. X+Start cancels naming. The file is a new .mss in /Moonshine data/states.
  3. Later, with the same mod build, game region and launcher setup, enter the same level and episode. Secret areas also need the same parent episode.
  4. Open SD states > Refresh / first page and highlight your file.
Button on a fileAction
Y Load fromMakes this file the target of your normal Load shortcut. Your three memory slots stay intact.
A ImportAfter confirmation, copies the file into the Save to slot. Load from stays unchanged.
Start RenameEdits the display name. Start finishes; X + Start cancels.
X DeleteDeletes the SD file after confirmation. Memory states are unaffected.
  • Loading from SD reads the file each time, so it can be slower than a memory load.
  • Large files can load even when all three slots are full, as long as one slot holds a working state for the current scene. That state is the recovery point: if a read fails mid-load, the game restores it and tells you which slot it used. With no recovery state and too little temporary space, the load is refused safely.
  • The game checks that its loaded resources match the state, so a matching level name alone may not be enough. Unsupported, incompatible or damaged files are refused before a memory slot is replaced.

  3. 再起動後は、同じmodビルド・ゲーム版・ランチャー設定で起動し、同じステージとエピソードへ入ります。秘密コースは、入る前の親エピソードも一致させます。

TAS projectsTASプロジェクト

A TAS keeps Mario's recorded inputs, its Beginning and up to two checkpoints together under one name.

  1. New TAS where the recording should begin. The Beginning is saved automatically, including the RNG, and gameplay stays paused.
  2. Hold Mario's buttons and press Step to record one frame, or Resume to record normal play. Opening the menu pauses your work.
  3. Checkpoints > Save Checkpoint 1 before a move you might redo. Go to Checkpoint 1 returns there; Step or Resume records a new continuation. Checkpoint 2 works the same way.
  4. Replay plays the inputs from the Beginning. B or Start stops it.
  5. Save TAS, enter a name and confirm with Start. It saves the whole recording, the Beginning and any checkpoints to /Moonshine data/tas. Later saves update the same TAS.
  6. Open TAS later with the same build, region and setup. In the list, Start renames and X deletes the SD copy, with confirmation.
  • Go to Beginning, Go to Checkpoint and Open TAS leave you paused and ready to edit. Later inputs stay available for Replay until your first new Step or Resume.
  • Continue stays paused so you can set up the next input. Use it after stopping a take or finishing a Replay.
  • Saving over a checkpoint asks first: A replaces, B keeps it.
  • Limits: 4096 frames and 32 area or movie transitions per take. The header shows the count, for example 200/4096. Inputs during intros, fades, talks and movies are recorded too; loading waits use no frames. If a limit is reached, recording stops and the take is kept.
  • TAS projects use the same three memory slots as savestates. If a new TAS needs an occupied slot, it asks which state to replace.
  • Replay is experimental. If the game differs from the recording, DESYNC fN shows the first frame that differed and playback continues. f0 means the starting state already differed.
  • For Replay and Go to Beginning, return to the area and episode where the TAS began yourself.
  • TAS banner (On by default) shows progress and help text. Turn it off here or in Display > Other HUD.
  • TAS projects can't be shared across regions or builds. Export a ghost to share a finished attempt.

What a ghost shows

  • Since V2.3.3, new recordings show FLUDD, nozzle changes, upper-body animation, spray, droplets, floor splashes and ground shadows. The water is a visual approximation and can't affect gameplay. Older files without FLUDD data behave as before.

Watch and Watch2

  • Watch plays one ghost; it skips movies and keeps the ghost's movement timing. Watching one ghost activates standing platforms, including the final Sirena 4 secret platform. Racing stays visual only.

  • B or Start leaves Watch. The menu combo opens the menu without ending it. Pause, Step and free camera all work while you watch.

TAS ghosts and savestates

  • Recordings made with practice pause, free camera or stepping are marked TAS. Their playback leaves out paused time. TAS ghosts are for practice and can't set an ordinary PB.

Tips and reportsヒントと不具合の報告

Gotchas

  • Bind overlaps: the attempt counter's Show and Add binds share D-Left / D-Right with savestates, which is why they only work with In-stage counter controls On.
  • Z and the warp wheel: leave Disable Z Menu On, or Z also opens the retail menu.
  • Binds need an exact match. If one won't fire, check that you aren't holding an extra button.
  • TAS next to the timer means the attempt used an assist. Restart the stage for a PB-eligible attempt.
  • A state won't load? You need the same stage and episode, build and setup. Savestate errors show unless you turned Savestate errors Off.
  • No Gecko codes. Keep Cheats off in the launcher's Settings; Moonshine already includes nearly all the GCT generator practice codes. Turn Native Controls on there too (not on Wii U).

Reporting a problem

  • Include the game region, scene, settings, steps to reproduce and the build checksum shown in game.
  • Crash history is in /Moonshine data/crashes, up to 16 recent reports. Keep the matching text, .bin and .core files from the same report together. The optional tools/decode_crash.py script reads the binary reports with Python 3.
  • Questions and reports go to the Moonshine Discord or the GitHub issues.

注意点

  • ボタンの重なり：試行カウンターの表示・追加は、ステートと同じ十字キー左右を使います。そのため In-stage counter controls がOnのときだけ使えます。
  • Zとワープホイール：Disable Z Menu はOnのままにしてください。Offにすると、Zで本来のメニューも開きます。
  • 割り当ては完全一致が必要です。反応しない場合は、余分なボタンを押していないか確認してください。
  • タイマーの横の TAS は補助を使った試行という意味です。PB対象の試行にするにはステージを再開してください。
  • ステートが読み込めない場合：同じステージとエピソード、同じビルドと設定が必要です。Savestate errors をOffにしていなければエラーが表示されます。
  • Geckoコードは使わないでください。ランチャーの Settings で Geckoコード（Cheats）はオフにしてください。GCT generatorの練習コードはほぼすべて内蔵済みです。同じ画面でGCコントローラ直接接続（Native Controls）もオンにしてください（Wii Uを除く）。
